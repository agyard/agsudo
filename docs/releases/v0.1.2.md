# AG-sudo v0.1.2

This release makes AG-sudo dependable inside agent hosts, where tool calls time
out and have no terminal, while keeping the CLI smaller. It keeps the daemonless
architecture and the v1 JSON protocol.

## Waiting, timeouts and resuming

- After about two seconds a waiting `sudo` names its request:
  `sudo: waiting for approval of req_…; see 'sudo --help'`.
- Only Ctrl-C cancels a waiting request. If a host times out or kills the
  wait, the request stays pending until it expires. Running the same command
  again in the same session reuses it — with any input piped to it — and runs
  it once approved, or reports a recent denial with the reviewer's reason
  instead of asking again. A new `--reason` replaces a pending request instead
  of duplicating it, and answers a denial with a fresh request.
- Denials show the reviewer's reason and how to ask again. A command that does
  not start exits 1 and says why, like sudo, instead of 124–127.
- `sudo --help` and `agsudo help --requester` print the same short guide, and
  the Claude Code integration tells the model at session start how approval
  works. `sudo -n` runs an already approved request and otherwise fails
  without submitting anything; `exec -n` is removed; `sudo -k` is accepted;
  `-E` and `VAR=value` explain how to pass variables.
- Commands get the caller's umask combined with `0022`, as with sudo, instead
  of `0077`.

## Execution and signals

- The CLI replaces itself with the helper instead of relaying to it. One
  Ctrl-C now reaches the command once (it previously arrived up to three
  times), SIGTERM/SIGHUP are no longer turned into SIGINT, and Ctrl-\ no longer
  crashes. A backgrounded `exec` behaves like a normal job and never signals or
  takes the terminal from other jobs.

## Reviewing

- Commands render as shell words (`dnf install -y 'a b'`); arguments with
  invisible or control characters use `$'…'`. Caller text stays on one line,
  context lines get a `│` gutter, and wrapped lines start with `↪`, so
  requester text cannot imitate decision lines. Shell requests are labelled.
- The TUI keeps the selected request across decisions, refreshes and filters,
  filters by substring, fits 80x24, shows both ends of the command when
  confirming, and says when details continue below. Tab focus and the `t` and `s` keys are removed;
  PgUp/PgDn always scroll details.
- `agsudo approve` at a terminal shows the request and asks for confirmation,
  naming the command (and any shell scope) at the prompt.
  `agsudo review` at a terminal also lists `needs_human` requests, like the TUI.
- `watch` follows new events by default; `--after 0` replays all history.
  Reviewer scripts should start `watch` before listing with `review`.
- Guardrails against agent mistakes when deciding without a terminal (or with
  `--json`): `approve` requires `--expect-digest`, `deny` and `defer` require
  `--reason`, and `needs_human` requests are left to people. Nobody can approve
  a request from their own `AGSUDO_SESSION`; decisions record that session.
  These are not a boundary against a hostile process.
- `--json` errors are JSON wherever the flag appears. Request IDs are shorter,
  and requests no longer include an empty `executor` object.

## Removed

`review --watch`/`--after` (use `watch`), the global `--helper` flag (use
`AGSUDO_HELPER`), `wrap --reason` and `AGSUDO_REASON` (which leaked one reason
into unrelated requests), `--summary`/`--recommend` on approve and deny, the
hidden `audit export --format`, the integration config backup and lock file,
and pre-generated completion files (use `agsudo completion SHELL`).

## Fixes

- Expired requests in other sessions no longer fill the per-user quota.
- Housekeeping runs in one transaction per call instead of one per request.
- The Codex hook passes commands through unchanged outside Full Access instead
  of denying every Bash call; its preamble is one line. Reinstalling or
  uninstalling reports and makes no change when nothing changes.

To upgrade, extract the archive for your architecture and run from a non-root
user's shell:

```sh
sudo ./scripts/install.sh "$(id -u)"
agsudo doctor
```

Upgrade the CLI and helper together; the installer preserves the existing
configuration and database. Installed host integrations keep working; scripts
that relied on the removed options or on exit codes 124–127 need updating.
