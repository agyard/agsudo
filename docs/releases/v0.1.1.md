# AG-sudo v0.1.1

This release improves the agent and human review experience while retaining the
daemonless architecture and v1 JSON protocol.

- Help separates command reference from workflow guides: `COMMAND --help` and
  `help COMMAND` remain available, with agent guides at `help --requester` and
  `help --reviewer`. The top-level `requester` and `reviewer` pseudo-commands are
  removed; sudo help and approval wait hints use the new entry points.
- `watch` keeps only the event-related `--session` and `--after` filters;
  `review --watch` remains supported. `review` no longer silently ignores an
  inapplicable `--after` or overrides conflicting `--all --state` options.
  `status` is now an alias for `show`, with unchanged response data. Audit export
  always uses JSONL.
- Fixed `exec --request ''` accidentally creating a new request. Resuming a
  request now explicitly rejects options that would override its submission.
- `show` and the TUI include the requester UID/GID, submission mode, and execution
  environment. Wide tables truncate commands and reasons to fit the terminal,
  preserving complete request IDs, states, and targets; piped output remains
  complete. The TUI makes confirmation of deferral to a human clearer and no
  longer shows an approval hint when denying a shell request.
- The repository and Go module moved to `github.com/agyard/agsudo`. Release
  archives continue to support Linux amd64 and arm64.

To upgrade, extract the archive for your architecture and run from a non-root
user's shell:

```sh
sudo ./scripts/install.sh "$(id -u)"
agsudo doctor
```

Upgrade the CLI and helper together; the installer preserves the existing
configuration and database. Update scripts using the old role help commands to
`agsudo help --requester` or `agsudo help --reviewer`. Subscribe to events with
`agsudo --json watch` and continue using `review` for filtered request lists.
For automated calls, put `--json` before the subcommand.
